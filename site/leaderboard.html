— METHODOLOGY

How rows are computed

Each router is run deterministically over all scenarios. Per-turn routing decisions are compared to the expected_router_actions / acceptable_alternatives oracle sets. Eleven submetrics are aggregated into the composite score. See Metrics for definitions and weights.

— ECOSYSTEM LEADERBOARD

Vendor routing capabilities

A capability survey of real-world routers — not the AgentRoute Score benchmark. These are LLM gateway / model routers (failover, load-balancing, per-prompt model selection), not multi-turn agentic routers, so they can't be scored on the 51 trajectory scenarios. The two open-source vendors were independently tested in our sandbox; closed-source vendors show vendor-claimed capabilities from their docs. Full methodology: docs/vendor-testing.md.

  • Fallback on failure: dead primary deployment → fell back to backup, returned backup's response ✓

  • Latency- & cost-based routing run but need real usage data to be meaningful (not exercised with mocks)

Kiro Gateway

AGPL-3.0 · FastAPI
  • Full test suite: python -m pytest -q → 1691 passed, 0 failures (7.5s)
  • Covers OpenAI/Anthropic streaming, Kiro stream parsing, error/timeout handling, multi-account failover & config validation

PASS   Agentic fit: none — an account-failover proxy, not a model router.

Position Single-turn routers answer "which model for this prompt?" AgentRoute Arena answers "which agent, tool path, handoff, or clarification across this evolving goal?" — the multi-turn, goal-based complement to the systems above. Not Diamond & AWS Kiro are the closest existing systems to agentic routing (session / multi-agent aware); the rest are single-turn selectors or failover proxies.
