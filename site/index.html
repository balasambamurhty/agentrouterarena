01 — THE PROBLEM

Single-turn routing breaks the moment a task spans turns

An LLM router optimizes "which model answers this prompt best." That question is meaningless once a task has a goal that evolves, a state that changes, and a pool of agents and tools to choose among.

LLM routing · one turn

Picks a model per prompt

  • ○ Unit of decision: a single prompt
  • ○ Signal: prompt text only
  • ○ Decision space: model pool
  • ○ Failure: wrong model picked
Agentic routing · multi-turn

Picks a policy across the trajectory

  • ● Unit of decision: a step in an evolving trajectory
  • ● Signal: goal, state, prior turns, tool results, failures, budget
  • ● Decision space: agents, tools, handoffs, splits, escalations, stops
  • ● Failure: stale goal, wrong specialist, over-clarification, loops
02 — THE POLICY

An agentic router is a policy engine over five things

Goal

What outcome is the user actually trying to achieve?

State

What has happened, failed, or been learned so far?

Capabilities

Which agents and tools can act, under what permissions?

Constraints

Budget, latency, privacy, risk, completeness.

Trajectory

Continue, re-route, split, escalate, clarify, or stop.

04 — GET STARTED

Run a router in three commands

# clone & install
git clone https://github.com/agentroute/agentroute-arena.git
cd agentroute-arena && pip install pyyaml jsonschema

# run the baseline router against all 31 scenarios
python evaluator/evaluate.py \
  --router evaluator/example_router.py \
  --scenarios benchmark/scenarios \
  --out results.json
