Submit a router

A router is any Python object implementing decide(ctx) → RouteDecision. Fork the repo, implement the interface, run the evaluator, open a PR.

  1. Implement the interface

    Create a class with a name attribute and a decide(ctx) method returning a RouteDecision. See evaluator/router_interface.py.

  2. Add your router

    Place it at submissions/<your-router>/router.py with a short README.md describing the policy.

  3. Run the evaluator

    python evaluator/evaluate.py --router submissions/<your-router>/router.py --out submissions/<your-router>/results.json

  4. Open a PR

    CI re-runs the evaluator and validates scenarios. Your row appears on the leaderboard once merged.

— THE CONTRACT
class AgenticRouter:
    name: str

    def decide(self, ctx: TurnContext)
        -> RouteDecision:
        ...

# ctx carries: scenario_id, family,
# user_goal, available_agents,
# constraints, history (prior turns
# + your prior decisions),
# current_user_message, current_tool_result,
# turn_index.

# return: route_to, action, reason
# action in: route | handoff |
#   clarify | split | escalate | stop

— RULES

What makes a valid submission

deterministic

Deterministic

Same trajectory → same decisions. Fix any RNG seed.

no-live-calls

No live calls in the loop

The evaluator replays synchronously. Benchmark measures routing policy, not tool execution.

self-contained

Self-contained

Use only what's in TurnContext; don't read scenario files at runtime.
